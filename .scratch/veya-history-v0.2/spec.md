# Veya 历史视图与内容类型 v0.2

Status: ready-for-agent
Feature: veya-history-v0.2
Implementation: 文件、图片、固定功能已接入；跨应用 Windows 验收仍按各 issue 跟踪

## 目标

让历史页上可点击的筛选、排序和视图按钮都产生真实、可解释的结果；在现有文本流的基础上增加文件、图片和固定记录。继续保留来源、粘贴触发及其置信度，不把“观察到粘贴快捷键”说成已插入内容。

## 当前事实（2026-09-23 工作区）

- “全部／文本／链接／代码／文件／图片”与“已固定”均接入真实筛选；固定可与内容分类叠加。文件、图片按真实剪贴板载荷归类，`format.rs` 只从文本推断普通文本、链接或代码。
- `veya-windows` 捕获 `CF_HDROP`、`CF_DIBV5`、`CF_DIB` 和 `CF_UNICODETEXT`，按优先级只产生一个原始事件；core、SQLite 和桌面端已接入载荷与固定字段。旧文本库迁移、回拷和自动清理有自动化测试。
- 隔离 Windows 实例已验证三项本地文件列表和 3×2 图片的捕获、重启恢复、筛选、详情与重新复制；Veya 自身回拷不新增历史。图片固定后重启仍保留，文件与图片分类可与固定筛选组合。真实 Explorer 粘贴、浏览器图片及不同图片格式的应用链路仍待验收。
- “最新优先／最旧优先”菜单和紧凑／详细列表切换已有代码与局部测试；02、03 的 Windows 实际点击、滚动和布局验收仍单独跟踪。历史卡片由 `veya-core/src/aggregate.rs` 产出。

术语按仓库根目录的 [CONTEXT.md](../../CONTEXT.md)：文件和图片是剪贴板载荷类别，“已固定”是跨类别的保留状态，不是第三种内容类型。

## 已确定的交互

- 默认仍为“最新优先”和当前详细列表。排序菜单先提供“最新优先／最旧优先”；右侧列表按钮切换“紧凑／详细列表”。排序、搜索、筛选和视图密度可以组合使用，切换时尽量保持当前选中记录。视图密度只需在本次运行期间保留。
- “文本”指普通文本；“链接”和“代码”是按内容识别的文本子类，三种筛选互斥。文件路径字符串仍是文本，不因为长得像路径就伪装成文件。
- “文件／图片／已固定”在对应数据能力交付前应呈禁用状态，不得把全部记录显示为这些类型，也不得显示虚假的数量。
- 固定记录跳过自动到期清理，直到用户手动取消固定或删除；用户明确执行“清空全部历史”时也会删除固定记录。固定状态保存在本机数据库，重启后仍有效。
- 固定状态落在原始记录，而不是临时聚合的历史卡片；对一张历史卡片固定/取消固定时，操作该卡片当时包含的全部原始记录。固定和未固定记录不能聚合为同一张卡片，避免新复制的内容意外继承固定状态。
- 同一次剪贴板变更只生成一条记录。扩展捕获时优先判定真实文件列表，其次真实图片，最后文本；不能靠扩展名或字符串猜类型。具体 Windows 格式覆盖和大小上限由基础数据任务验证后定稿。

## 验收边界

- 用真实运行中的 Windows 剪贴板验证文本、文件列表、图片各自的捕获、重启恢复、筛选、详情、重新复制、删除和粘贴触发关联；小型核心/存储测试覆盖排序与清理规则。编译通过不能代替这些行为检查。
- 非文本记录不能被错误解析为 UTF-8 文本；未知或超限格式需安全跳过并显示可理解的状态，不写入半条记录。
- 虚拟文件/OLE 专有对象、云同步、浏览器精确 URL、图片 OCR、按使用次数排序和网格视图不在这轮范围。

## Windows 格式依据

- Microsoft 文档说明 `CF_HDROP` 是现有文件位置列表，Shell 虚拟对象另有格式：https://learn.microsoft.com/en-us/windows/win32/shell/clipboard
- Microsoft 标准格式文档列出 `CF_DIB`、`CF_DIBV5` 等图片格式：https://learn.microsoft.com/en-us/windows/win32/dataxchg/standard-clipboard-formats
