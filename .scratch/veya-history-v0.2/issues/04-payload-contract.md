# 04：多类型剪贴板载荷与持久化契约

Status: ready-for-agent
Blocked by: none

## 要做什么

在现有文本记录基础上确定文本、现有文件路径列表、图片三种载荷的核心模型、SQLite 迁移、序列号身份、内容哈希、聚合、粘贴触发关联、重新复制接口和删除/清理契约。保留旧数据库文本历史。先用可运行的小型原型或测试验证 Windows 格式覆盖、图片编码及合理的单条大小上限，再把这些结果写入本任务的 `## Decisions`，供 05/06 实现。

领域边界：一个剪贴板变更只接受一种优先载荷并生成一条原始记录；文件列表、图片、文本按顺序尝试，不能从文件路径字符串推断真实文件载荷。内容哈希必须区分载荷类别，不能让相同字节的不同类别误聚合。固定状态是原始记录的保留属性，不进入内容哈希，也不产生新的载荷类别。历史卡片可以聚合原始记录，但重新复制必须选定可重放的实际载荷。

## 实施前决策门槛

- 文件：明确 `CF_HDROP` 的本地文件/文件夹路径列表如何保存与重放；移动/删除后复制的结果和提示；是否保存复制/剪切意图。虚拟文件不纳入本轮。
- 图片：实测 `CF_DIB`、`CF_DIBV5` 与常见截图/浏览器样本，定保存编码、尺寸与字节上限、超限反馈和重放格式。
- 身份：同一剪贴板序列带多个格式时只写一条；Veya 对文本、文件、图片的内部写入都应被抑制；不同原始记录的粘贴触发不能串线。
- 迁移：旧文本库读写兼容、失败回滚、自动到期和手动删除的语义，须在迁移测试后定稿。

这些结果写入本票 `## Decisions` 后，再把 05/06 从 `needs-info` 转为 `ready-for-agent`。

## 验收

- 旧版数据库打开后文本历史完整；迁移失败不会造成旧记录丢失。
- 多类型记录在重启后保持载荷与类型，复制 A、复制 B 的粘贴触发仍不串联；同一序列不会因多种剪贴板格式并存而重复入库。
- 明确文件仅保存路径列表还是复制内容；明确图片持久化编码、大小上限与超限行为；决定重新复制各类型时的内部写入抑制方法。
- 核心与存储测试覆盖迁移、序列身份、删除/自动清理和不可识别载荷；为 05/06 提供稳定接口。

## Decisions（2026-09-23）

- 载荷由 core 的 `ClipboardPayload::{Text, Files, Image}` 表示。`content` 是搜索和列表用的文字投影，重新复制只使用真实载荷；纯文本路径始终是 `Text`。同一剪贴板序列只选一种，优先级为 `CF_HDROP`、`CF_DIBV5`、`CF_DIB`、`CF_UNICODETEXT`。
- `CF_HDROP` 保存现有文件或文件夹的有序绝对路径列表，不保存文件内容或剪切意图。历史重放一律按复制处理；任一路径失效即在修改系统剪贴板前失败并提示。虚拟文件不在本轮。限制为 4096 项、单路径 32767 个 UTF-16 单元、列表 4 MiB。
- 图片在 Windows 消息线程上只复制有界 DIB 字节，worker 解码并规范化为 PNG。支持 `CF_DIBV5` 优先、`CF_DIB` 回退；持久化 PNG 和宽高，重放为 `CF_DIBV5`。上限为 16 Mi 像素、原始 DIB 64 MiB、PNG 32 MiB；损坏、超限或当前无法保留的嵌入色彩配置文件安全跳过。此覆盖范围仍须用实际截图工具和浏览器样本确认。
- 聚合使用包含载荷类别的稳定哈希；文件路径按顺序及长度参与，图片按规范化 PNG 与尺寸参与。内部重放抑制同时核对写入后的剪贴板序列及精确的 Veya owner PID，以容忍 Windows 读取图片时重新编码造成的字节差异；纯逻辑测试覆盖不同 owner 不被误抑制，真实 Windows 文件和图片回拷已验证不新增 Veya 记录。
- SQLite 保留旧 `content TEXT` 列，新增可空 `payload BLOB`、图片宽高和原始记录 `pinned` 列；文件列表 BLOB 用 JSON 编码，图片 BLOB 为 PNG。迁移在事务内执行，旧文本库默认未固定。自动清理跳过固定，明确清空仍删除全部记录。迁移、回滚、类型往返和固定清理已有自动化测试。

## Implementation status

核心、存储、Windows 和桌面 UI 已接入。隔离实例验证了文件列表及图片捕获、重启恢复、分类与详情、文件 `CF_HDROP` 和图片回拷、固定筛选与重启持久化；用户旧文本库副本迁移前后均为 88 条。文件重放曾因 `DROPFILES` 字段顺序错误而失败，按 Microsoft 结构定义修正后，Windows `FileDrop` 读取到 3 个仍存在的路径。Explorer → Veya → Explorer、浏览器图片和真实跨应用粘贴目标仍待验收，本票尚未关闭。
