# 04：按职责拆分桌面端 app.rs

Status: done
Blocked by: 01, 03

## 要做什么

在弹窗和单例交互稳定后，将 `app.rs` 约 2100 行按消息路由/状态、历史列表、详情、设置及纯展示辅助拆成 `app/` 子模块。保持 App 对 Iced 的入口和现有用户行为，不新增 crate，也不把核心语义复制到视图模块。整理模块可见性，避免让整个 App 状态成为各视图的任意可写接口。

## 验收

- `main.rs` 继续只负责装配；消息更新仍有单一入口；历史筛选/排序/密度、详情弹窗、设置和快捷键行为不变。
- 核心状态转换可由现有或少量新增的行为测试覆盖；Windows 1080×700 窗口实际核对选中、弹窗和滚动。
- 拆分本身不改数据库 schema、不调整剪贴板业务语义。

## Implementation

- `veya-desktop/src/app.rs` 保留启动、消息路由、订阅和主壳层；`history.rs`、`detail.rs`、`settings.rs` 分别承载历史工具栏/列表、详情与完整内容弹窗、设置面板。
- 子模块通过 `pub(super)` 暴露视图方法，消息更新仍只有 `App::update` 一个入口；筛选、排序、列表密度、选中、详情菜单、二维码、设置和快捷键逻辑保持原实现。
- 未移动或重写 Win32/shell 副作用，留给 issue 05；未修改数据库 schema、worker 或核心流程语义。
- 验证：`cargo check -p veya-desktop` 和 5 项桌面端测试通过。随后使用隔离 `APPDATA` 实际启动 1080×700 窗口，核对文本记录、详细/紧凑列表、排序下拉和完整内容弹窗；选中和弹窗显示正常。
