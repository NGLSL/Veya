# 整体代码与内存优化规划

## 目标

在快捷粘贴、完整历史搜索、来源线索和 typed replay 的体验不下降的前提下，减少历史页重读、PNG 载荷搬运、全量 clone 和重复存储写入。只围绕当前可定位的开销与生命周期问题优化，不做无证据的全仓重构。

## 必须保留的行为

- 原始记录与聚合卡片分离；聚合窗口、原始 ID、source confidence、pin、内容类型和排序保持现有语义。
- 搜索覆盖完整历史、完整文本和已有来源／使用字段；不能以截断内容或只搜索缓存换取内存数字。
- 图片预览和原图按需读取，重放仍能取得完整原 payload；分页跨批次分组不漏、不重。
- 粘贴仅是观察到的尝试。新持久化接口不能改变事件含义或导致内存状态与数据库静默分歧。
- 不以明显延迟唤起、卡顿滚动、丢失查询状态或改变保留策略降低内存。

## 验收方法与边界

先用固定数据集核对新旧查询、分组、分页和存储结果，再使用同一 Windows 环境、同一数据库、同一操作序列测量空闲后台、首次唤起、搜索、翻页、图片预览和隐藏后的资源。记录进程 private bytes、working set、峰值和操作耗时；缓存、GPU／解码器资源与持久数据库大小分别解释。绝对阈值以实测基线确定，不能凭编译成功宣称内存降低。

当前仅 01／06 已落入实现，相关 worker 自动测试及隔离 Windows 对照已通过：相同 100 条文本／图片夹具、开发构建和 wgpu，管理首页 Private Bytes 从 304,132,096 降至 263,946,240 bytes，Working Set 从 269,373,440 降至 212,615,168 bytes。该结果是单次场景测量，不能推为所有环境的稳定降幅。构建哈希、行为验收与未验证项见 [运行报告](../veya-quick-paste/validation/report.md)。其他票据是后续实施计划，不能标为已完成。
