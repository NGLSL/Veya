# 整体代码与内存优化规划

## 目标

优先保证首页和 Alt+V 首屏快速可用，在保留完整历史搜索、来源线索和 typed replay 的前提下，减少历史页重读、PNG 载荷搬运、全量 clone 和重复存储写入。用户允许后续翻页、历史搜索、详情和原图按需加载时有短暂等待，以换取较低的常驻内存；等待不能阻塞窗口交互。只围绕当前可定位的开销与生命周期问题优化，不做无证据的全仓重构。

## 加载优先级

- 首屏优先：窗口、搜索框、最近一页的内容预览和可选择／粘贴状态先可用。首屏可用以实际出现可操作的最近记录为准，不能只测空窗口显示时间。
- 延后读取：后续页、展开的全文、使用详情和原图由用户操作触发；完整搜索按输入触发。避免为了潜在后续操作提前装载整段历史或大 payload。
- 图片分阶段显示：文字／类型线索先可用，缩略图随后补齐；评估持久化小缩略图，避免每次打开列表都先解码原图。已有历史按需生成缩略图，不能在启动时全量回填。
- 缓存有界：优先复用当前首屏的必要数据；后续大内容在关闭、切换或隐藏后释放。是否保留少量首屏预览缓存，以后台内存与再次唤起耗时的对照结果决定。
- 等待明确：后续加载显示加载状态，窗口仍可搜索、取消或关闭；新查询／会话不能被旧请求的迟到结果覆盖。可接受等待不代表允许结果不完整、误选或误粘。

## 必须保留的行为

- 原始记录与聚合卡片分离；聚合窗口、原始 ID、source confidence、pin、内容类型和排序保持现有语义。
- 搜索覆盖完整历史、完整文本和已有来源／使用字段；不能以截断内容或只搜索缓存换取内存数字。
- 图片预览和原图按需读取，重放仍能取得完整原 payload；分页跨批次分组不漏、不重。
- 粘贴仅是观察到的尝试。新持久化接口不能改变事件含义或导致内存状态与数据库静默分歧。
- 不以明显延迟首屏可用、阻塞窗口交互、丢失查询状态或改变保留策略降低内存。后续按需加载允许短暂等待，并明确显示加载状态。

## 验收方法与边界

先用固定数据集核对新旧查询、分组、分页和存储结果，再使用同一 Windows 环境、同一数据库、同一操作序列测量空闲后台、首次唤起、搜索、翻页、图片预览和隐藏后的资源。分别记录冷启动与再次 Alt+V 到最近记录可选择／粘贴的耗时、缩略图补齐耗时，以及后续加载等待时间。首屏速度优先验收；后续加载重点验收窗口响应、取消、结果正确性和内存收益。记录进程 private bytes、working set、峰值和操作耗时；缓存、GPU／解码器资源与持久数据库大小分别解释。绝对阈值以实测基线确定，不能凭编译成功宣称内存降低。

01／06 第一轮的相关 worker 自动测试及隔离 Windows 对照已通过：相同 100 条文本／图片夹具、开发构建和 wgpu，管理首页 Private Bytes 从 304,132,096 降至 263,946,240 bytes，Working Set 从 269,373,440 降至 212,615,168 bytes。该结果是单次场景测量，不能推为所有环境的稳定降幅。第一轮证据见 [快捷面板运行报告](../veya-quick-paste/validation/report.md)。

本轮落入 02 的首页／按需加载范围及 05：workspace 115 项测试通过；单机对照冷启动到实际选中记录约 1882 → 1268ms，隐藏后再次 Alt+V 的两次样本约 618／540 → 238／232ms。管理首页 Private Bytes 约 249.0 → 240.3 MiB（首次生成小图），已有小图缓存为 225.1 MiB。首次生成后隐藏的私有内存约比基线高 2.5 MiB，不能宣称全部后台场景下降。矩阵、构建哈希、限制与最终窗口验收见 [本轮运行报告](validation/report.md)。02 的跨页游标复用、03、04 仍未实施。
