# 02：历史 metadata 投影与查询游标

Status: ready-for-agent
Priority: P1
Blocked by: 01
Implementation: 首页优先加载、轻量投影及按需内容已实现并验证；查询游标复用保留后续

## 根因与负责范围

`worker.rs::load_history_page` 每页从 `cursor = None` 扫描，按 `page * HISTORY_PAGE_SIZE` 跳过匹配卡片；`Store::load_records_page` 的 SELECT 同时读取 `payload` PNG BLOB。后面的页会反复搬运前面记录的图片，即使它们不显示。负责 storage 的窄 metadata 查询、worker 分页和可见页 payload 装载。

## 方案

扫描只取分组、筛选和完整搜索需要的 metadata／文本／paste 线索；页内显示与 typed replay 按原 record ID 读取完整 payload。为同一查询记录聚合边界处的分页游标；查询或数据变化时明确失效，不设无界缓存。先定义窄数据契约，不改变 core 的现有语义。

按首页优先安排读取：最近页预览与可选择状态优先发布，后续页、全文详情和原图由操作触发。完整搜索保留原有语义，可有明确的加载等待。缩略图可随后补齐，评估持久化小缩略图与已有记录按需生成，避免首屏反复解码原图或启动全量回填。任何新增分阶段加载必须避免旧查询结果覆盖新查询；加载期间取消／关闭仍可响应。

## 验收

- 固定文本、图片、文件、pin、source confidence 和长重复组的数据集，新旧排序、搜索结果、卡片代表 ID 与分页完全一致。
- 等时间戳、跨 batch 聚合、前后翻页和 mutation 后游标不漏、不重；全文搜索不截断。
- 非当前页 PNG 不经历史扫描解码／搬运；原图展开和 replay 仍可取得完整 payload。
- 实测冷启动与再次 Alt+V 到最近记录可选择／粘贴的耗时，首页快速可用优先；缩略图补齐单独计时。
- 实测后页翻页、完整搜索和详情的读取量、峰值内存与等待时间。用户允许后续按需加载有短暂等待；加载状态明确、窗口可响应，新旧查询结果不会串用。

## 本轮实施与验证

已实现 `Store::load_history_page`（图片不取 PNG BLOB、文本单份全文投影）、后台最新请求加载、结果代数校验、先发布卡片后逐张补齐缩略图、SQLite 有界小图缓存、逐行生成常规 PNG 缩略图、512 字符卡片摘要和单条全文按需读取。搜索仍匹配完整代表内容；原图与 typed replay 使用完整原记录。自动及实际 Windows 检查见 [运行报告](../validation/report.md)。

按照用户允许后续加载等待的取舍，本轮优先完成首页与大内容的延后加载。分页仍使用现有从头扫描的轻量查询；跨页游标复用尚未实施，不标为完成。Status 保持 ready-for-agent 表示此后续范围仍在。
