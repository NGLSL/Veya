# Veya 字体与隐藏窗口资源性能报告

> 清理记录（2026-10-23）：原始测量数据、日志、统计、脚本及测量时的报告已合并为 `performance-evidence-2026-10-23.zip`，保留在本地同目录，不随源码发布；包内保留原目录结构。临时夹具、源码快照和可执行文件已清理；下文路径与复现命令为测量时记录，原临时运行环境已不存在。

日期：2026-10-23。正式测量时间：10:47:32–10:53:31（America/Los_Angeles）。环境：Windows 11 10.0.26300 x64，16 个逻辑处理器，Rust 1.99.0，Iced 0.13 CPU tiny-skia / Windows softbuffer。原生窗口的 OS DPI 为 96；100%／200% 由程序绘制缩放控制，并核对实际物理像素尺寸。

这轮优化在 25 条普通文本场景中降低了字体与绘图资源的内存占用。管理窗口 100% 显示时 Private 中位数从 **25.48 MiB 降到 12.48 MiB（降低 51.0%）**，隐藏时从 **25.48 MiB 降到 8.67 MiB（降低 66.0%）**。恢复需要重建绘图缓存：隐藏后显示的画面就绪中位数从 **3.62 ms 增至 20.75 ms**；200% 管理窗口从 **3.61 ms 增至 43.17 ms**。内存收益和恢复开销分别列在下表。

本报告比较本轮优化前的完整工作区快照和优化后的候选快照。基线已经包含此前共享文本/PNG、搜索分配和大图峰值优化；没有使用 Git HEAD 代替本轮基线。

有效样本共 **80 个独立进程**；每种窗口形态、缩放、渲染路径和构建各 **N=5**。下面为中位数，时间同时列出最小值与最大值。内存单位为 MiB（1 MiB = 1,048,576 字节）。

## 字体阶段与 25 张卡片的归因

离屏阶段分开观察：进程进入 main → 创建 App 和 25 张卡片 → 安装字体 → renderer → UI build → UI draw → 像素缓冲 → raster。该路径用于区分文字数据、字体目录/预热、布局与绘图缓存的占用；真实隐藏行为的数据以上面的原生窗口为准。

| App + 25 张卡片 | 3.50 → 3.50 | 10.25 → 10.28 | 4 → 4 |

管理界面的暖帧绘制耗时接近：100% 时三帧总耗时的 N=5 中位数除以 3，为 9.60 → 9.54 ms/帧；200% 为 30.92 → 30.44 ms/帧。这是三帧均摊值，不是独立单帧延迟的 P50；本轮没有据此宣称持续绘制性能显著提升。

cosmic-text 保留完整系统字体扫描和按需字体加载；本轮去掉当前未启用 `monospace_fallback` 功能的等宽字体缓存/脚本索引预热。前后均观察到 **558 个字体 face、273 个字体族**，默认中文字体为 **Microsoft YaHei UI**，目录摘要一致；线程变化是此特定字体构造阶段的记录，Iced/Tokio 运行时仍会建立自己的线程。

## 行为与数据完整性

- 每个原生样本核对测量进程自己的 HWND、Win32 可见/最小化状态、实际 client 尺寸、真实 viewport 尺寸和缩放、present 成功状态。
- 管理窗口 200% 的实际 surface 为 2160×1400；快捷窗口 200% 为 880×1160，逻辑布局大小保持一致。记录同时包含 OS DPI 与 program scale。
- `initial` present 记录是 Ready(get_latest) 后的匹配帧；之前 boot 阶段可能已经完成绘图。本报告没有把该时间当作应用冷启动或首可见帧延迟。
- 隐藏期间还把逻辑尺寸增加 60×40、程序目标缩放乘 1.25，然后恢复。按新物理尺寸实际配置 surface 并绘制成功；实际跨显示器的 OS DPI 迁移另需人工运行验收。
- 每个进程初始画面、隐藏后恢复和最小化后恢复的实际像素摘要一致；前后构建相同场景的摘要一致。隐藏 resize/scale 后的新画面也进行前后比较。
- 普通文本前部含中文、English、emoji、日语、韩语、阿拉伯语、俄语、印地语、泰语；保留多语言字体回退画面。画面一致性证明本机现有显示行为保持一致，不推断所有机器的字体可用性。
- 累计 CPU 记录含 Toolhelp 全系统线程枚举、日志等观测开销，本报告没有用相邻阶段累计 CPU 差宣称隐藏空闲 CPU 的改善。

## 测量边界与可复现信息

原生 Harness 使用真实 Iced event loop、`ChangeMode`、`Minimize`、真实 `App::view()` 和 vendored tiny-skia/softbuffer present；App 状态为隔离构造。没有执行 Veya `App::boot()`、业务 `App::update()`、worker、数据库、托盘、全局键盘 hook 或剪贴板业务。故表中数值用于比较本轮渲染/字体改动，不能直接替代完整日常安装进程的内存读数或人工 Alt+V 体验验收。

本轮运行从可见窗口开始，随后执行隐藏、最小化和恢复。初始 `visible: false` 启动及隐藏窗口的 `window::Screenshot` 动作已做静态审查，未单独运行；物理跨显示器 DPI 切换也未在本轮操作。

每个样本均启动新 release 进程；没有清理 Windows 文件缓存；保持正常 CPU affinity 和正常 Rayon 并行度；前后构建按重复次数交替执行，全部顺序运行，测量期间没有并行 Cargo 构建。
