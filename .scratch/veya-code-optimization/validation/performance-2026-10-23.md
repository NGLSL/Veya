样本：17 组场景 × 基线/候选 × 5 次独立进程，共 170 次。

状态：同机源码路径对照完成；真实安装版窗口、完整系统剪贴板发布与目标应用粘贴未纳入本轮。

## 先回答：一页只有几十条，为什么仍占这么多内存？

本轮普通页面使用 25 条短文本，原文合计只有 **7,325 字节，约 7.15 KiB**。真实 `App::view()` 与当前 `tiny-skia` 渲染器离屏绘制后的候选进程，在 100% 缩放下约 **21.39 MiB 私有内存、34.07 MiB 工作集**；200% 缩放下约 **32.78 MiB 私有内存、45.40 MiB 工作集**。

主要固定成本来自字体系统、界面布局/字形缓存和像素缓冲。字体初始化这一步使私有内存从约 3.45 MiB 增至 15.23 MiB，增量约 11.8 MiB；100% 下明确申请的 RGBA 与 mask 共约 3.60 MiB，200% 下为 14.42 MiB。卡片数量与进程占用因此没有简单的线性关系。

这组短文本即使大幅压缩，正文层面的节省上限也只是数 KiB。普通页面的下一步应优先调查字体加载范围和绘图资源生命周期；文本压缩适合单独针对大正文工作集评估。

## 本轮优化的实测结论

- **普通短文本页基础占用基本持平。** 100% 离屏页面 Private Bytes 为 21.48 → 21.39 MiB；200% 为 32.71 → 32.78 MiB。此轮没有减少字体与绘图基础成本。
- **大文本历史查询峰值约减半。** 128 条大文本混合库的未命中查询进程峰值提交为 21.16 → 10.62 MiB，首轮查询耗时 570.88 → 661.11 ms。
- **大图重放准备峰值下降约 31%。** 本组 4K 图片样本为 177.82 → 122.31 MiB，准备耗时 48.47 → 92.21 ms，保留了新增摘要计算的实际成本。
- **PNG → DIBV5 同时改善峰值和耗时。** 峰值提交 98.53 → 66.83 MiB；23.11 → 15.07 ms。
- **DIB → PNG 捕获转换的总峰值改善很小。** 峰值提交 223.45 → 221.68 MiB，约下降 0.8%；不能用移除一份 DIB 封装副本推算整条编码链路的峰值收益。
- **存在检索时间代价。** 900,000 字节中文正文的单次核心查询中位数为 4.03 → 4.76 ms，约慢 18%；混合大文本库的完整扫描约慢 16%–18%。

采样程序直接复用对应快照的 core、storage、历史加载器、App 视图、tiny-skia 渲染器和图片转换函数。为访问私有图片准备函数及 App 构造状态，只在临时副本中附加测量入口；产品没有增加性能入口或测试用例。

所有表格均汇总独立进程的中位数。核心搜索先从每个进程的 20 次真实函数调用计时中取中位数，再对 5 个进程取中位数；没有把循环内构造 JSON 统计对象的耗时算作搜索调用时间。未命中与尾部命中各占一半，分类结果保存在汇总 JSON。

Windows 文件缓存未清理。历史查询的首轮只称 **process-first**，含义是本进程打开数据库后的首次查询；后两轮为同进程暖查询。数据库打开和迁移排除在查询计时之外。报告不包含安装版启动时间或窗口可交互时间。

## 普通 25 条文本页的占用分解

界面使用 1080×700 逻辑尺寸、25 张详细列表卡、短详情与相同字体/图标 fallback。没有创建原生窗口、worker、托盘或全局 hook。

| 候选离屏进程阶段 | 100% Private MiB | 100% Working Set MiB | 200% Private MiB | 200% Working Set MiB |
| --- | ---: | ---: | ---: | ---: |
| App 与 25 张短文本卡准备完成 | 3.45 | 10.09 | 3.45 | 10.09 |
| 字体系统初始化完成 | 15.23 | 25.41 | 15.02 | 25.19 |
| 真实界面组件树与布局完成 | 17.38 | 29.09 | 17.48 | 29.10 |
| RGBA 画布与 mask 分配完成 | 21.07 | 29.93 | 32.01 | 29.23 |
| 首次渲染并完成 3 个暖帧 | 21.39 | 34.07 | 32.78 | 45.39 |
| 释放 App、UI、renderer 和画布对象后 | 15.69 | 28.46 | 15.84 | 28.54 |

这些数值是采样进程各阶段的总占用，不是每个对象的精确分配大小；阶段之间还包含 allocator、首次格式化和全局缓存影响。对象释放后的残余值包含仍存活的全局字体系统与堆保留。

RGBA 与 mask 的明确字节数为：100% 时 3,024,000 + 756,000 = **3,780,000 B（3.60 MiB）**；200% 时 **15,120,000 B（14.42 MiB）**，随缩放比例平方增长。

| 普通页结果 | 基线 Private MiB | 候选 Private MiB | 基线 Working Set MiB | 候选 Working Set MiB |
| --- | ---: | ---: | ---: | ---: |
| 100% 缩放，暖帧 | 21.48 | 21.39 | 34.09 | 34.07 |
| 200% 缩放，暖帧 | 32.71 | 32.78 | 45.37 | 45.39 |

每暖帧绘制时间：100% 为 8.56 → 9.67 ms；200% 为 30.82 → 31.09 ms。两边 UI 像素摘要完全一致。本轮没有修改该 UI 渲染链路，这些时间差保留为观察值，不归因为文本共享带来的提升。

真实应用还包含原生窗口、compositor、后台 worker、SQLite 连接和系统交互，因此离屏值不能直接当作安装版进程的总占用或承诺。

## 4K 大图转换与重放准备

固定 3840×2160 图片，确定性 RGB 高熵数据、alpha=255。PNG 为 **33,182,358 字节（约 31.65 MiB）**，代表编码后仍很大的压力图片，保留在现有 32 MiB PNG 限制内。它不代表普通截图的压缩率或透明图片。

内存为 **OS 记录的进程峰值提交**。读取文件、输入摘要及只读图片头获取维度均在操作计时之前；计时内包含真实转换，以及候选产品准备路径本身需要的 SHA-256。

| 场景 | 基线内存 MiB | 候选内存 MiB | 内存变化 | 基线耗时 ms | 候选耗时 ms | 耗时变化 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| PNG → DIBV5 | 98.53 | 66.83 | -32.2% | 23.1096 | 15.0691 | -34.8% |
| DIBV5 → PNG | 223.45 | 221.68 | -0.8% | 129.4073 | 118.4965 | -8.4% |
| 重放前全部系统缓冲准备 | 177.82 | 122.31 | -31.2% | 48.4667 | 92.2119 | +90.3% |

重放准备两边均创建三份真实 GlobalAlloc 系统缓冲，合计 **91,243,322 字节**，PNG、DIBV5、24 位 DIB 的摘要逐一一致。候选用约 55.5 MiB 更低的峰值提交换取约 43.7 ms 的准备时间增加。

该场景停在清空剪贴板之前，未调用 OpenClipboard、EmptyClipboard、SetClipboardData 或目标应用粘贴。它不包含发布后的重新打开、摘要读回确认或按键/目标应用时延；完整重放延迟需要独立 Windows 验收。

捕获转换的峰值仍超过 220 MiB，说明这一路径继续有值得分析的编码/分配峰值。现有数据仅支持“移除封装复制对整条链路总峰值改善很小”，尚未把剩余峰值精确归因到 PNG 编码器、缓冲扩容或分配器。

## 数据一致性与计数边界

五次配对中，文本 payload hash、命中数、历史卡片数/原始序列校验和/预览字节/has_next、图片输入输出与三格式系统缓冲摘要、UI framebuffer SHA-256 均一致。UI/image 的候选标识与构建身份一致；源码与二进制哈希保存在 manifest 中，并已独立复核。

- Private Bytes：测量时刻本进程的私有提交量；Working Set：当时驻留物理内存的工作集，包含可共享页。
- OS 峰值提交：PROCESS_MEMORY_COUNTERS_EX 的 PeakPagefileUsage，是进程生命周期的峰值提交计数；并非精确定位某条语句的峰值 PrivateUsage。
- 1 ms 线程采样的 Private Bytes 峰值为观察下界，调度可能漏掉更短分配；原始数据保留每轮采样次数。主表没有把这个下界当作精确峰值。
- 各阶段总占用和各进程峰值包含测量工具本身的固定成本。CPU 测量固定单逻辑处理器，不等于真实应用在所有设备、多核负载下的表现。
- 所有最终数值只取 `final-results.jsonl`。早期诊断记录不进入本报告统计。

## 交付与后续优先级

1. 普通页面优先调查字体系统初始化和常驻缓存，以及高 DPI/隐藏窗口时的绘图资源生命周期。字体、中文/emoji fallback 与首次显示速度应一同评估。
2. 保留本轮降低副本与峰值的改动，并继续处理中文检索时间代价。图片重放准备的时间增加已量化，应在完整真实重放验收中一并观察。
3. 单独分析 DIB → PNG 的剩余高峰值；当前总峰值改善有限。
4. 文本内存压缩按大正文存续期评估。普通 25 条短文本页的正文很小，对基础占用的优先级低于字体和绘图资源。

本轮没有替换或重启日常安装版，日常 Veya PID 39240 与原启动时间保持。未提交、未升版、未发布；不把安装版现有进程读数当作候选收益。新增的是独立性能采样工具，现有测试场景保持，最终 workspace 129 项测试及格式、检查、开发版构建通过。
