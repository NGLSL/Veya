# Veya v0.2.6

补齐微信、QQ、Chrome 和截图工具的剪贴板采集兼容性，新增常见图片格式采集与本地视频静态封面，并移除两处界面说明小字。

## 复制内容更完整

- 改善应用内点击“复制”、右键复制和截图复制的采集。剪贴板短暂被其他程序占用时，以 25 ms 间隔异步重试，同一序列最多等待一秒，期间热键和消息循环保持响应；新的复制会替换尚未读到的旧内容。
- 修复微信、QQ 图片同时提供临时文件路径和图片像素时，只保存文件路径、无法显示图片预览的问题。单文件同时附带图片表示时优先保存可解码的图片；图片全部无效则保留原文件，纯文件和多文件复制继续按文件处理。
- 增加注册格式 PNG、JPEG（含 JFIF/JPG）、WebP、GIF 及常见 MIME 别名的采集，与已有 DIB／DIBV5 一起按优先级尝试。一种表示无效时继续尝试其他表示，同一剪贴板序列只记录一次。
- 图片统一保存为 PNG；有效 PNG 保留原始字节，GIF 和动态 WebP 保存首帧静态图。格式尺寸和内存预算在解码前检查，避免损坏或超大图片造成不受控分配。
- 等待读取期间观察到的粘贴快捷键跟随对应的剪贴板序列；成功采集后及时更新状态提示。

## 视频文件显示静态封面

- 单个本地视频文件在管理列表、快捷面板和详情中显示静态封面，支持尝试 MP4、MOV、MKV、WebM 等常见扩展名。使用 Windows 原生缩略图接口，无需安装或附带 FFmpeg。
- 先显示可选择、可复制的记录，再由历史后台线程串行补齐最长边 128 像素的封面，不阻塞剪贴板事件 worker 或界面。
- 封面只保留当前页缓存，按文件大小和修改时间失效；窗口隐藏、最小化或进入设置页后释放缓存和缩略图 reader，正在进行的系统取图返回后再释放。
- 视频继续归在“文件”类别，重新复制提供原视频路径。多文件复制、源文件失效或系统无法生成封面时，保留文件条目和文件图标。

## 界面整理

- 移除侧栏的“你的剪贴板，有记忆。”。
- 移除关于版本下方的“Clipboard Flow Tracker · 记住从哪来，去向何处。”。

## 升级与数据

- 可覆盖安装旧版，历史和设置继续保存在 `%APPDATA%\Veya\veya.db`；安装与卸载保留用户数据，本版没有数据库迁移。
- 已有视频文件记录在源文件仍存在且系统支持取图时即可显示封面，无需重新复制。
- 之前保存为文件的聊天图片保持原文件记录；重新从聊天应用复制后，按新的图片优先规则采集。Veya 不读取磁盘图片来改写已有记录。

## 验证

- 本地格式检查、锁定依赖的 workspace 检查和现有 129 项测试通过，release 安装包构建通过；本次没有新增或修改测试用例。
- 在 Windows 11 隔离历史中，实际验收微信、QQ 图片采集与预览，Chrome 右键文本／图片复制、截图复制、短暂剪贴板占用恢复，以及图片重新复制后的格式与自身记录抑制。
- 使用两条真实微信／QQ HEVC 视频记录，实际查看管理列表、快捷面板和详情封面；隐藏、进入设置页、重新打开后预览正常。重新复制仍为原视频文件路径，未新增 Veya 自身复制记录。
- 修复构建已在本机通过项目安装器覆盖更新并查看日常视频历史，原有历史记录与设置保持不变。该交互验收在版本号更新前完成。

## 使用条件

- 视频封面取决于 Windows 的缩略图处理程序和解码器；首次解码可能带来短暂的系统宿主内存峰值。Veya 串行取图并只保留小尺寸封面，不保存视频内容，也不提供视频播放。
- 图片最多 16,777,216 像素；单份 DIB 不超过 64 MiB，每类编码图片候选合计不超过 32 MiB，同次采集候选合计不超过 96 MiB。超限或所有图片表示均无效时可能跳过；单文件附带图片的情况保留文件路径。
- 安装包未签名，Windows 可能提示未知发布者。
