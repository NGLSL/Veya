# Veya v0.2.1

此版本修复历史记录占用过多内存、托盘或 `Alt+V` 唤起不够连贯，以及 Windows 软件渲染路径短暂露出原生标题栏的问题。

## 变化

- 历史页改为从 SQLite 按游标分页读取，每页只保留 25 张历史卡片；搜索、分类、固定筛选和排序仍作用于完整历史。
- 窗口隐藏、最小化或停留在设置页时释放已发布的历史卡片，重新打开历史页时再读取。
- 图片历史列表只生成最长边不超过 128 像素的缩略图，完整图片在打开大图时才按序列号读取，并在关闭或切换时释放。
- 移除不必要的字体数据库依赖，减少常驻内存。
- 默认恢复 Iced 的 `wgpu` 渲染器，避免 `tiny-skia` 在 Windows 托盘恢复首帧时短暂露出原生标题栏。软件渲染器仍可通过 `ICED_BACKEND` 手动诊断。
- 缩短窗口信号和 worker 快照的等待间隔，减少 `Alt+V`、托盘唤起和历史加载的可感知延迟。
- 保留顶部透明拖动区域，移除可见的“拖动窗口”文字控件。

## 升级与数据

- 可直接覆盖安装 v0.2.0。
- 历史和设置继续保存在 `%APPDATA%\Veya\veya.db`，升级不会删除已有数据。
- 本次提交没有改变现有剪贴板载荷类型、固定状态或粘贴使用记录的语义。

## 验证与限制

- 已通过 `cargo fmt --all -- --check`、`cargo check --workspace` 和 `cargo test --workspace`；workspace 测试共 68 项。
- 已通过 `cargo build --release -p veya-desktop`。
- Windows 隔离数据运行中，使用含 104 条历史的数据库连续验证托盘隐藏/唤起和前后台切换；默认 `wgpu` 路径未再出现原生标题栏闪现。
- 安装包构建、覆盖安装和其他机器上的真实 Windows 交互仍需在发布流程中单独验收。
