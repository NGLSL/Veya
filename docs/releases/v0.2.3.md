# Veya v0.2.3

这个版本改用 CPU 绘制界面，减少窗口常驻内存；同时减少大图片转换时的完整像素副本，并将粘贴使用线索改为单条追加，避免每次触发都重写原内容和全部旧线索。

## 窗口与渲染

- 参考 Kite 的后端选择方式，关闭 Iced 默认特性并显式启用 `tiny-skia`。当前构建不包含 `wgpu` 后端，保留图片、SVG、中文字体和主题功能。
- 修复软件渲染器遇到零面积布局时的崩溃，覆盖快捷面板按 Esc 收起和直接打开“管理历史”时，窗口尚未恢复大小的过渡状态。
- 修复最小化恢复后界面内容未变时跳过呈现，导致窗口持续透出下层内容的问题；Windows 下重新提交已有像素缓存，无需重复绘制整幅画面。
- 保留此前隐藏窗口的重绘调度修复，避免收起后持续占用一个 CPU 核心。

## 图片与使用线索

- 捕获 DIB 图片时直接读取解码图尺寸，省去仅用于尺寸检查的完整 RGBA 副本。
- PNG 重放时消费已有解码缓冲，再分配目标 DIB，减少同时存活的完整像素副本；保留颜色、alpha 和现有大小限制。
- 每次观察到粘贴只追加一条使用线索，保留旧线索 ID，不重写 PNG 或旧线索。数据库写入成功后才更新内存状态；写入失败会反馈错误，并保留原内存／存储状态。
- 清理开发期验证目录，长期保留自动回归测试、开发验收要求及本地依赖补丁说明。

## 升级与数据

- 可覆盖安装 v0.2.2，历史和设置仍保存在 `%APPDATA%\Veya\veya.db`；安装与卸载保留用户数据。
- 本版没有数据库迁移，不改写历史载荷、固定状态、来源置信度或已有使用线索。
- `Alt+V`、完整历史搜索、按原类型重放和按需查看原图的入口保持一致。

## 验证与性能证据

- 本地格式检查、workspace 检查、123 项测试、release 编译、Windows GUI 子系统检查及 NSIS 安装包构建通过。新增回归覆盖真实 CPU 绘制、图片颜色格式和尺寸校验、旧线索保留、数据库重开，以及写入失败时数据库与内存状态的一致性。
- Windows 11、16 个逻辑处理器的隔离运行验证了中文／图片显示、原图弹窗、快捷面板隐藏、三次反复唤起、直接进入管理历史、系统及自绘按钮最小化恢复。实际图片重放与外部捕获的全部像素一致，四次粘贴触发只追加四条使用线索，原始载荷与旧 ID 保留。
- 同一批 100 条文本／图片历史、相同开发构建配置的单机对照中，管理窗口 Private Bytes 约 242.38 → 29.78 MiB，Working Set 约 193.90 → 57.85 MiB；快捷面板 Private Bytes 约 250.66 → 27.59 MiB，隐藏后约 250.79 → 26.30 MiB。CPU 构建隐藏时的短时采样为 0.29%，按 16 个逻辑处理器归一；这些是指定夹具的整个进程测量，不是显存分项或所有机器的性能承诺。
- 独立 Windows 转换子进程的三次峰值提交量中位数：4096×2160 捕获约 150.32 → 116.44 MiB，重放约 114.56 → 80.70 MiB；4096² 嵌入 PNG 捕获约 238.89 → 173.09 MiB，纯重放约 214.55 → 150.84 MiB。十二次前后输出摘要全部相等；未扩大实际剪贴板大小限制。
- 发布门禁在一次性 Windows runner 执行真实安装、覆盖升级、已安装程序哈希／版本及快捷方式核对、卸载和用户数据保留检查。桌面交互证据来自上述本地隔离运行。

## 已知限制

- 最小化恢复后，在首幅软件画面提交前仍可能短暂透出下层内容。本机最早约 46–60 ms 的截图观察到过渡画面，约 93–106 ms 时已正常显示；本版修复持续失绘，但不保证恢复第一帧完全无闪烁。
- 本轮资源对照使用开发构建，没有测安装版性能、长期资源曲线、多显示器／不同缩放或其他硬件。
- 图片检查验证剪贴板类型重放和观察到的粘贴尝试，不证明目标应用插入图片；原生 EDIT 测试宿主不支持图片插入。普通权限向管理员应用发送按键仍受 Windows 权限限制。
- 安装包未签名，Windows 可能提示未知发布者。
