# Veya v0.2.5

修复历史图片重新复制后无法粘贴进 QQ 的兼容性问题。直接截图和 Windows `Win+V` 可以粘贴的图片，现在通过 Veya 的快捷面板或重新复制继续使用。

## 图片粘贴

- 图片回放同时提供原始 PNG、保留透明度的 DIBV5 和传统 24 位 DIB，让目标应用读取其支持的表示。此前只主动提供 DIBV5，其他位图表示依赖 Windows 自动转换。
- 传统 DIB 使用标准 40 字节位图头、自底向上的行与 DWORD 对齐，不再依赖目标应用接受系统转换出的 32 位位图变体。
- PNG 与 DIBV5 保留原透明度；传统 DIB 不支持透明度，透明像素合成到白底。DIBV5 同时补齐图像颜色转换意图。
- 所有格式的编码与剪贴板内存准备完成后才清空旧内容；写入后逐一核对原始字节。部分写入失败继续取消自动粘贴，避免误贴旧内容或错误释放已交给 Windows 的内存。

## 构建与升级

- 纳入已在开发分支验证的 Rust 1.99.0 工具链固定配置，本地构建、CI 与发布使用同一版本。
- 可覆盖安装 v0.2.4，历史和设置保存在 `%APPDATA%\Veya\veya.db`；安装与卸载保留用户数据。
- 本版没有数据库迁移。已有图片历史可直接使用新的回放方式，无需重新截图或复制。

## 验证

- 用户已确认修复后的 QQ 图片粘贴通过实际验收。
- 本地格式检查、锁定依赖的 workspace 检查、开发版构建及现有 129 项测试通过；本次没有新增或修改测试用例。
- Windows 11 隔离数据目录中，实际回放 2048×2048 图片后读回 PNG、DIBV5 和传统 24 位 DIB，系统可以读取完整尺寸的位图。回放前后原始记录数量均为 105，没有重复保存 Veya 自己的写入。
- 发布门禁重新执行 workspace 检查、release 安装包构建，以及一次性 Windows runner 中的安装、覆盖升级、程序版本与哈希、快捷方式、卸载和用户数据保留检查；其结果见本次 CI 与 Release 工作流。

## 已知限制

- QQ 的实际粘贴由用户确认；隔离运行检查验证剪贴板内容与自身记录抑制，不代替其他目标应用的逐项验收。
- 传统 24 位 DIB 的透明区域为白底；支持 PNG 或 DIBV5 的目标应用可读取带透明度的表示。
- 安装包未签名，Windows 可能提示未知发布者。
