# 发布说明

发布前创建 `vX.Y.Z.md`，写清用户可见变化、升级影响、验证范围和已知限制。提交说明不能代替发布说明。

发布标签必须是与 `veya-desktop` 版本一致的注释标签，并指向默认分支上已经通过 CI 的提交。推送标签后，Release workflow 才会构建安装包、生成 SHA-256 并创建 GitHub Release。配置或文档提交本身不会发布版本。

标签推送后若工作流在发布前失败，可修复默认分支上的工作流，再通过 `workflow_dispatch` 传入同一个标签重试；重试必须重新通过全部发布门禁，不移动标签。具体命令见 [开发规范](../DEVELOPMENT.md)。
